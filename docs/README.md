# EPGS 文档索引

本文件是 `docs/` 的目录。**先读第 1 节**——它解释了为什么仓库里还有一个名字很像的
`Doc/` 目录，以及哪些内容**不应该**出现在这里。

## 1. `docs/` 与 `Doc/` 是两个不同性质的目录

仓库根目录下同时存在 `docs/` 和 `Doc/`，只差一个字母的大小写，但它们的分工是明确的，
不是历史遗留的重复目录：

|                | `docs/`（本目录）                        | `Doc/`                                        |
| -------------- | ---------------------------------------- | --------------------------------------------- |
| 版本控制       | **纳入**（`git ls-files docs` 可见）     | **整体被忽略**（`.gitignore` 的 `Doc/` 规则） |
| 内容           | 需要长期维护、评审、随代码演进的项目文档 | 医院提供的样本、需求原始材料、截图、工作草稿  |
| 能否进部署目标 | 可以                                     | **绝对不可以**                                |

`Doc/` 被忽略是有意设计，理由记在 [`.gitignore`](../.gitignore) 第 41–49 行的注释里，
本节复述要点：

- 里面有**医院提供的真实导出样本**和**真实 SOAP 抓包**，未完成脱敏评审前不得提交；
- 其中 mock 导出文件名使用 **U+2011 非断行连字符**（`moke‑data.csv`），ASCII 连字符的
  忽略模式匹配不到它，所以用**目录级忽略**一次性覆盖；
- **堡垒机必须对着真实 SOAP 网关运行，绝不能用本地 mock 数据**，因此该目录
  **不得存在于部署目标上**。

判断新文档放哪：**需要随代码一起演进、别人 clone 下来就能看到 → `docs/`；
一次性的过程材料或含真实数据的样本 → `Doc/`，并且不要提交。**

## 3. 新增文档时的约定

1. 放在 `docs/` 下，文件名用小写英文加连字符（如 `user-admin-api.md`）。
2. 接口类文档命名 `<模块>-api.md`，设计类命名 `<模块>-design.md`，界面类命名
   `<模块>-ui.md`。
3. 在本文件第 2 节的对应分组里补一行，否则新文档没有入口。
4. 涉及范围取舍时，以 [acceptance.md](./acceptance.md) 为准并在文档内链过去，
   不要让两份文档各自表述同一件事。
